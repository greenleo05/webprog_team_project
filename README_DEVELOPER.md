# 💻 컴공생 마법소녀의 하루: 기술 사양서 및 개발자 가이드

본 문서는 `game.js` 코드의 작동 메커니즘, 상태 관리 구조, 렌더링 파이프라인, 그리고 수학적 충돌 물리 수식을 상세히 기술합니다. 동료 개발자가 프로젝트를 분석하거나 면접/질의응답을 준비할 때 완벽히 대비할 수 있도록 비유를 제외하고 공학적 관점에서 모든 로직을 설명합니다.

---

## 1. 전역 변수 및 객체 스키마

### 1.1 UI 요소 엘리먼트 바인딩
* `canvas` / `ctx`: 게임 화면을 그리는 `HTMLCanvasElement` 및 2D 렌더링 컨텍스트.
* `scoreDisplay`, `livesDisplay`, `timeDisplay`, `stageNameDisplay`, `timerDisplay`: 실시간 UI 데이터 바인딩 엘리먼트.
* `pauseBtn`, `pauseOverlay`, `settingsOverlay` 등: 모달 제어용 DOM 객체.

### 1.2 이미지 로딩 및 실시간 픽셀 전처리 (CORS 대응)
* `magicalGirlImg` 객체를 로드한 즉시 인메모리 캔버스(`tempCanvas`)를 활용해 `getImageData`로 RGBA 픽셀 배열을 분석합니다.
* 픽셀 데이터 루프를 돌며 R > 240, G > 240, B > 240에 해당하는 흰색 및 미색 영역의 알파 채널(`data[i+3]`)을 `0`으로 수정하여 투명 처리를 수행합니다.
* **CORS 방어**: 로컬 파일 시스템에서 직접 `index.html`을 브라우저에 띄울 경우 보안 규칙에 의해 `getImageData`가 거부(SecurityError)될 수 있으므로, `try-catch` 블록으로 이를 감싸 에러 발생 시 원본 이미지를 그대로 대체하게 처리했습니다.

### 1.3 게임 제어 및 상태 변수
* `isGameRunning` / `isPaused`: 메인 루프 업데이트와 사용자 입력을 분기하기 위한 플래그 변수.
* `isDevMode`: 개발자 시연 모드(쉬움)와 실제 유저 모드(어려움) 간의 밸런스를 분기하기 위한 전역 상태 변수.
* `score` (총 누적 점수), `lives` (플레이어 잔여 목숨, 초기 기동 시 10으로 할당되나 게임 실행 시 3으로 재설정), `currentStageIndex` (현재 활성화된 스테이지 배열 인덱스).
* `maxUnlockedStage`: 로컬스토리지 `maxUnlockedStage` 키값에서 가져온 도달 최고 스테이지(기본값 0).
* `timeLeft` (남은 시간 초, 60초 시작), `lastTime` (1초 감소 여부를 판정하기 위한 이전 시스템 타임스탬프).
* `BASE_SPEED`: 공의 전체 속력 크기를 정의하는 스칼라 상수 (`Math.sqrt(3*3 + 3*3) ≈ 4.24`). 방향 벡터 분할이 일어나더라도 언제나 일정한 물리 속력을 가지도록 수학적인 기준으로 삼습니다. (개발자/유저 모드 공통 적용)

### 1.4 핵심 물리 객체 스키마
* **`paddle`**: 가로 크기(`width`), 세로 크기(`height`), 좌표(`x`, `y`), 색상 정보 정의.
* **`ball`**: 중심 좌표(`x`, `y`), 속도 벡터(`dx`, `dy`), 반지름(`radius`), 리스폰 제어 필드(`isRespawning`, `respawnTimer`).
* **`bricks`**: `bricks[col][row]`의 구조를 갖는 2차원 배열. 벽돌 객체는 `{ x, y, status, hp, type, offsetX }` 형태를 가집니다.
* **`boss`**: 5스테이지 보스 오브젝트. 체력(`hp`), 상태 페이즈(`phase`), 활성화 상태(`active`), 반지름(`radius`), 이동 속도 벡터(`dx`, `dy`), 피격 무적 제어(`lastHitTime`)를 포함합니다.

## 2. 스테이지 생명 주기 및 데이터 관리

`stages` 배열의 각 원소는 아래 속성을 갖는 독립된 시나리오 객체입니다.
* `time` (UI 표기용 문자열), `name` (스테이지명), `desc` (설명글), `bgColor` (게임 백그라운드 색상)

* `isCleared()` (클리어 검증 함수)

2. **Stage 1 (교수님의 지루한 수업) [10:00]**
   * 패들 크기: 150px
   * 벽돌 레이아웃: 개발자 모드 `2×4`, 유저 모드 `6×8`. 모두 `hp: 1`, `type: 'sleepy'`.
3. **Stage 2 (점심 보상 스테이지 - 학식) [12:00]**

   * 벽돌 레이아웃: 개발자 모드 `1×5`, 유저 모드 `4×9`. 모두 `hp: 1`, `type: 'food'`.
   * **특이 사항**: `draw()` 루프 내부에서 해당 인덱스의 바닥 충돌이 확인될 시 공을 낙하시키지 않고 `dy = -Math.abs(dy)`로 위로 강제 튕김으로써 무적 상태를 제공합니다.
4. **Stage 3 (조별과제) [17:00]**
   * 패들 크기: 150px
   * 벽돌 레이아웃: 개발자 모드 `2×5`, 유저 모드 `5×9`
   * **기믹**: 각 블록 배치 시 `troll` 타입 할당 확률이 개발자 모드 30%, 유저 모드 60%로 상승합니다.
   * **실시간 갱신 (`update`)**: `troll` 타입 블록들의 `offsetX` 값을 `Math.sin(Time / 150 + col + row) * 15` 공식을 사용하여 주기적으로 흔들리게 만들어 난이도를 높입니다.
5. **Stage 4 (과제 - 버그 물리치기) [23:00]**
   * 패들 크기: 150px
   * 보스 세팅: `boss` 객체를 Phase 1, 비활성화(`active: false`), 체력 `20`(유저 모드 `50`)으로 초기 설정. 체스판 형태로 빈 곳과 `bugcode` 타입 벽돌 교차 배치 (개발자 `2×3`, 유저 `4×6`).
   * **실시간 갱신 (`update`)**:
     * 에러 코드 벽돌이 모두 파괴되면 곧바로 전투를 시작하지 않고 `boss.phase = 2`로 진입하여 **경고 연출(3초)**을 수행합니다. 이때 화면이 흔들리며 붉은 배경과 점멸하는 경고 메시지가 출력됩니다.
     * 3초가 지나면 `boss.phase = 3`, `boss.active = true`로 전환되어 본격적인 전투 페이즈가 시작되며, 공의 Y축 속도를 위로 튕겨서 공격을 유도합니다.
     * 보스 활성화 시 `boss.x` 좌표에 `boss.dx`를 지속 가산하며, 벽 경계(`canvas.width - radius` 또는 `radius`)에 충돌할 때 방향 벡터 부호 반전(`boss.dx *= -1`).

## 3. 핵심 수학적 충돌 감지 및 물리 알고리즘

### 3.1 원(공)과 직사각형(벽돌/패들) 충돌 감지 (Circle-AABB Collision)
공과 사각형의 충돌 판정 및 연산 과정은 다음과 같습니다.

1. **가장 가까운 점 탐색 (Closest Point on AABB)**:
   직사각형 내/외부에서 공의 중심점 `(X_c, Y_c)`와 가장 가까운 좌표 `(X_t, Y_t)`를 한계점 제한(Clamp) 방식을 통해 도출합니다.
   ```text
   X_t = Math.max(x_rect, Math.min(X_c, x_rect + w_rect))
   Y_t = Math.max(y_rect, Math.min(Y_c, y_rect + h_rect))
   ```

2. **충돌 여부 검증 (Distance Check)**:
   공의 중심점과 구한 최단 점 사이의 거리 `D`를 구하여 공의 반지름 `R`과 비교합니다.
   ```text
   D = Math.sqrt((X_c - X_t)^2 + (Y_c - Y_t)^2)
   if (D <= R) -> 충돌 발생
   ```

3. **겹침 해결 (Overlap Resolution)**:
   프레임 지연으로 인해 공이 사각형 깊숙이 파고드는 연산 오차를 해결하고자 물리 위치를 보정합니다. 겹친 깊이(Overlap)는 `R - D`입니다.
   단위 법선 벡터 `(n_x, n_y)`를 구하여 공의 좌표에 보정 벡터를 더해 밀어냅니다.
   ```text
   n_x = (X_c - X_t) / D
   n_y = (Y_c - Y_t) / D

   X_c_new = X_c + n_x * (R - D)
   Y_c_new = Y_c + n_y * (R - D)
   ```
   *만약 두 점 사이의 거리 `D`가 0인 예외 상황(완전히 겹친 경우)에는 공을 강제로 패들의 높이만큼 위쪽으로 이동시킵니다.*

4. **충돌 반사각 벡터 연산 (Vector Reflection)**:
   법선 벡터 `N`과 공의 진행 속도 벡터 `V`의 내적을 이용해 속도를 반사합니다.
   ```text
   V_reflected = V - 2 * (V · N) * N
   ```
   *이때 다중 튕김 현상을 억제하기 위해 공이 사각형을 향해 이동 중인 음수 내적 상태(`V · N < 0`)일 때만 법선 반사를 허용합니다.*

### 3.2 패들 튕김 각도 조절 물리 (유도탄 앵글)
패들 상단면에 부딪혔을 때는 완전 탄성 반사를 적용하지 않고 플레이어의 컨트롤 요소를 가미하기 위한 상대적 위치 맵핑 반사 물리식을 활용합니다.

1. **상대적 위치 비율 계산**:
   패들 중앙점 기준 공이 맞은 실좌표의 이격 거리 및 정규화 비율(`-1.0 ~ 1.0` 범위)을 구합니다.
   ```text
   hitPoint = X_c - (x_paddle + w_paddle / 2)
   normalizedHitPoint = hitPoint / (w_paddle / 2)
   ```

2. **반사각도 및 속도 벡터 매핑**:
   최대 반사 각도를 좌우 60도(`Math.PI / 3`)로 한정하고, 공의 진행 속도 벡터 크기를 균일하게 맞춥니다.
   ```text
   bounceAngle = normalizedHitPoint * (Math.PI / 3)
   dx = BASE_SPEED * Math.sin(bounceAngle)
   dy = -Math.abs(BASE_SPEED * Math.cos(bounceAngle))
   ```
   이로써 공은 패들 윗면에 부딪힌 부위에 비례하여 조준 사격과 동일하게 제어할 수 있는 방향성을 얻게 됩니다.

### 3.3 원과 원의 충돌 판정 (공과 보스 캐릭터)
보스의 중심점 `(X_b, Y_b)`, 반지름 `R_boss`와 공의 중심점 `(X_c, Y_c)`, 반지름 `R_ball`의 유클리드 거리를 측정합니다.
```text
D = Math.sqrt((X_c - X_b)^2 + (Y_c - Y_b)^2)
if (D < R_ball + R_boss) -> 충돌 판정
```
충돌 시 공을 반지름 합산 거리 바깥으로 밀어낸 뒤 중심 기준 반사 각도로 리디렉션 처리합니다.
*보스의 무적 처리를 위해 피격 시 200ms 동안 추가 데미지가 발생하지 않도록 쿨다운 타임을 체크합니다.*

## 4. 메인 렌더링 루프 `draw` 분석 (714~827라인)

`requestAnimationFrame(draw)`에 의해 초당 60회 속도로 지속 루프 연산되는 게임 루프 시퀀스입니다.

1. **타이머 갱신**:
   `Date.now() - lastTime >= 1000` 판정을 거쳐 1초마다 남은 시간 `timeLeft`를 차감하고 UI 텍스트에 적용합니다.
2. **스테이지 개별 실시간 로직 처리**:
   현재 스테이지 인덱스에 따라 흔들리는 벽돌의 이동량 연산이나 보스(등장 연출 및 이동) 로직 처리를 구동합니다.
3. **공의 위치 변이 가산**:
   부활 대기 모드(`isRespawning`)가 아니라면 X, Y 좌표에 각각 방향 속도 `dx`, `dy`를 더해 줍니다.
4. **외벽 경계 Clamp 처리**:
   공의 좌표가 벽의 물리 한계선 바깥으로 이탈하지 않도록 차단하고 반대 방향 부호를 강제 할당합니다.
   * `x < radius` 이면 `x = radius`, `dx = Math.abs(dx)` (우측 반사)
   * `x > canvas.width - radius` 이면 `x = canvas.width - radius`, `dx = -Math.abs(dx)` (좌측 반사)
   * `y < radius` 이면 `y = radius`, `dy = Math.abs(dy)` (하단 반사)
5. **바닥 추락 판정 및 생명 주기 처리**:
   공이 캔버스 하단 경계(`y > canvas.height - radius`)를 통과한 경우 분기 처리를 수행합니다.
   * **Stage 2 (학식)**: 바닥을 튕김 처리하여 공의 소멸을 방지합니다.
   * **기타 Stage**: 목숨을 1 차감하고, 남은 목숨이 존재하면 패들 중앙 위쪽 150px 위치로 공을 옮긴 뒤 `isRespawning` 플래그를 올려 1초간 깜빡임 지연을 거친 후 아래로 다시 낙하시킵니다. 목숨이 없으면 루프를 중지하고 메인 UI 화면을 로드합니다.
6. **패들 충돌 감지**:
   패들 영역의 꼭짓점과 공의 원 간의 Closest Point 및 겹침 보정 공식을 수행해 윗면 충돌 시 정규화 각도 반사를 수행하고 옆면 충돌 시 수평 방향 반사를 실시합니다.
7. **화면 렌더링 파이프라인**:
   `ctx.clearRect(0, 0, canvas.width, canvas.height)` 함수로 캔버스 평면의 지난 픽셀을 싹 비운 후, 벽돌 ➡️ 보스 ➡️ 캐릭터 패들 ➡️ 공 순서대로 겹쳐 그리기를 수행하여 깊이 표현을 조정합니다.
8. **오브젝트 충돌 처리 및 스테이지 클리어 연산 (`collisionDetection`)**:
   벽돌과 공의 충돌 및 보스와 공의 충돌을 루프 본문과 독립적으로 처리하여 대상의 체력 값을 삭감하고 파괴 시 점수를 부여합니다. 모든 조건이 충족되면 남은 시간에 비례한 타임 보너스 스코어 계산 후 다음 스테이지 데이터 모달을 호출합니다.

## 5. UI 드로잉 및 이펙트 파이프라인

### 5.1 3D 입체 베벨 효과 구현 (`drawPixelBlock`)
레트로 디테일을 위한 드로잉 메서드로 아래의 드로잉 과정을 포함합니다.
1. `ctx.fillRect(x, y, w, h)`에 `#000` (검은색) 컬러를 채워 테두리 외곽 레이어를 구성합니다.
2. 2픽셀 안쪽 여백에 타겟 컬러로 내부 면적을 덮어씌웁니다.
3. 좌측/상단 방향으로 두께 3px짜리 반투명 흰색 영역을 그려 돌출 형태의 하이라이트 베벨을 생성합니다.
4. 우측/하단 방향으로 동일하게 3px 크기의 반투명 검은색 섀도우를 그려 들어가 보이는 음영 깊이감을 유도합니다.

### 5.2 리스폰 무적 상태 플리커 (Flicker) 연산
공이 소실되어 재생성 모드(`isRespawning: true`)에 들어가면, 현재 시각과 `respawnTimer`의 차이값(`elapsed`)을 계산합니다.
```text
flickerPhase = Math.floor(elapsed / 150) % 2
```
0일 때는 렌더링을 건너뛰고 1일 때만 그려지도록 제어하여 1초(1000ms) 동안 빠르게 점멸하는 효과를 완성한 뒤, 시간이 지나면 낙하 운동을 개시합니다.

### 5.3 메인 화면 및 오버레이 블러 처리
게임의 진행 상태(메인 메뉴 화면, 게임 일시정지, 게임 오버 등)를 명확히 하고 고급스러운 UI 경험을 제공하기 위해 오버레이 DOM(`main-screen`, `pause-overlay` 등)에 CSS 속성을 부여합니다.
* `backdrop-filter: blur(5px)` (메인 메뉴는 `8px`로 강화) 속성을 적용하여 뒷단에 위치한 Canvas의 픽셀 정보를 동적으로 흐리게 만듭니다.
