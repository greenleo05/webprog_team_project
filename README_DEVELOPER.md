# 💻 컴공생 마법소녀의 하루: 기술 사양서 및 개발자 가이드

본 문서는 `game.js` 코드의 작동 메커니즘, 상태 관리 구조, 렌더링 파이프라인, 그리고 수학적 충돌 물리 수식을 상세히 기술합니다. 동료 개발자가 프로젝트를 분석하거나 면접/질의응답을 준비할 때 완벽히 대비할 수 있도록 비유를 제외하고 공학적 관점에서 모든 로직을 설명합니다.

---

## 1. 전역 변수 및 객체 스키마

### 1.1 UI 요소 엘리먼트 바인딩
* `canvas` / `ctx`: 게임 화면을 그리는 `HTMLCanvasElement` 및 2D 렌더링 컨텍스트.
* `scoreDisplay`, `livesDisplay`, `timeDisplay`, `stageNameDisplay`, `timerDisplay`: 실시간 UI 데이터 바인딩 엘리먼트.
* `pauseBtn`, `pauseOverlay`, `settingsOverlay`, `helpOverlay` 등: 모달 제어용 DOM 객체.
* **메인 타이틀 히든 트리거**: `mainTitle`을 1초 내에 3번 연속 클릭 시 `main-mode-container`가 토글되어 숨겨져 있던 **개발자 모드**(스테이지 선택 기능 및 난이도 하향)를 켤 수 있도록 설계되었습니다.

### 1.2 이미지 로딩 및 실시간 픽셀 전처리 (CORS 대응)
* `magicalGirlImg` 객체를 로드한 즉시 인메모리 캔버스(`tempCanvas`)를 활용해 `getImageData`로 RGBA 픽셀 배열을 분석합니다.
* 픽셀 데이터 루프를 돌며 R > 240, G > 240, B > 240에 해당하는 흰색 및 미색 영역의 알파 채널(`data[i+3]`)을 `0`으로 수정하여 투명 처리를 수행합니다.
* **CORS 방어**: 로컬 파일 시스템에서 직접 `index.html`을 브라우저에 띄울 경우 보안 규칙에 의해 `getImageData`가 거부(SecurityError)될 수 있으므로, `try-catch` 블록으로 이를 감싸 에러 발생 시 원본 이미지를 그대로 대체하게 처리했습니다.

### 1.3 게임 제어 및 상태 변수
* `isGameRunning` / `isPaused`: 메인 루프 업데이트와 사용자 입력을 분기하기 위한 플래그 변수.
* `isDevMode`: 개발자 모드(테스트용, 쉬움)와 일반 유저 모드(어려움) 간의 분기를 제어하는 전역 상태 변수. 타일 배치 수 및 보스 패턴 난이도에 관여합니다.
* `score` (총 누적 점수), `lives` (플레이어 잔여 목숨), `currentStageIndex` (현재 활성화된 스테이지).
* `maxUnlockedStage`: 로컬스토리지 `maxUnlockedStage` 키값에서 가져온 도달 최고 스테이지(기본값 0).
* `BASE_SPEED`: 공의 전체 속력 크기를 정의하는 스칼라 상수 (`Math.sqrt(3*3 + 3*3) ≈ 4.24`). 방향 벡터 분할이 일어나더라도 언제나 일정한 물리 속력을 가지도록 수학적인 기준으로 삼습니다.
* `ultimateGauge` / `ultimateBgAlpha`: 스페이스바 필살기 게이지 및 발동 시 렌더링되는 배경 빔 이미지(`magical_beam.png`)의 투명도(페이드 인/아웃) 제어 변수.

### 1.4 핵심 물리 객체 스키마
* **`paddle`**: 가로 크기(`width`), 세로 크기(`height`), 좌표(`x`, `y`), 디버프 타이머(`debuffTimer`), 색상 정보 정의.
* **`balls`**: 다중 공 지원을 위한 배열. 중심 좌표(`x`, `y`), 속도 벡터(`dx`, `dy`), 반지름(`radius`), 리스폰 제어 필드 포함.
* **`bricks`**: `bricks[col][row]`의 구조를 갖는 2차원 배열. 벽돌 객체는 `{ x, y, status, hp, type, offsetX, offsetY, text, isRight }` 형태를 가집니다.
* **`boss`**: 5스테이지 보스 오브젝트. 체력(`hp`), 상태 페이즈(`phase`), 활성화 상태(`active`), 이동 속도 벡터(`dx`, `dy`) 및 투사체 타이머 포함.

## 2. 스테이지 생명 주기 및 데이터 관리

`stages` 배열의 각 원소는 아래 속성을 갖는 독립된 시나리오 객체입니다. 각 스테이지 시작 전, `pre_stage_n_bg.png`를 이용한 5초짜리 브릿지 컷씬이 타이머(`setTimeout`)와 함께 재생됩니다.

### 2.1 각 스테이지 구성 정보 및 기믹 상세
1. **Stage 0 (지하철 - 등굣길) [08:00]**
   * **기믹**: 모든 블록은 `Canvas API`를 사용해 사람(픽토그램) 형태로 드로잉됩니다. 일반 승객은 체력 1의 파란색, `isTroll` 판정을 받은 빌런 블록은 체력 2의 회색 베이스와 머리에 붉은 표식이 렌더링되어 충돌 및 체력 관리가 요구됩니다.

2. **Stage 1 (교수님의 지루한 수업) [10:00]**
   * **기믹**: 네모난 말풍선 형태로 렌더링됩니다. 조는 학생(체력 1, 하얀색)과 질문폭격기(체력 3) 블록으로 나뉘며, 질문폭격기는 체력에 따라 붉은색(`#ff4c4c`)에서 옅은 분홍색(`#ffcccb`)으로 색상이 동적으로 변화합니다.

3. **Stage 2 (점심 보상 스테이지 - 학식) [12:00]**
   * **기믹**: 음식 타입 난수 할당 및 도형 드로잉(샌드위치, 케이크 등). 바닥 충돌 시 `dy = -Math.abs(dy)`로 공을 강제로 위로 튕기며 무적 상태를 제공합니다. 스테이지 클리어 시 +2 라이프 보너스가 부여됩니다.

4. **Stage 3 (조별과제) [17:00]**
   * **기믹**: 카카오톡 텅 빈 채팅방 컨셉(`stage_3_bg.png` 사용)으로, 각 블록은 좌우 꼬리가 달린 노란/하얀 말풍선으로 그려집니다. 무임승차(트롤) 조원 블록이 아래로 서서히 낙하(`b.dropY`)하며, 공으로 맞추지 못하고 바닥(패들 라인)에 닿을 시 큰 점수 패널티(-50~-100점)를 받습니다.

5. **Stage 4 (과제 - 버그 물리치기) [23:00]**
   * **기믹**: 에러 코드 벽돌 파괴 후 보스(세미콜론) 페이즈 진입.
   * **버그 수정 사항**: 보스 체력 바 비율이 1초과로 렌더링 되는 버그 `Math.min` 클램핑 처리 완료. Canvas 상태 오염 누수 현상 `ctx.save()` / `ctx.restore()`로 독립성 확보.
   * **궁극기 배경 효과**: 보스전 등에서 게이지를 채워 스페이스바를 누르면 유성이 떨어집니다. 이때 화면 전역에 `magical_beam.png`가 서서히 렌더링(`ultimateBgAlpha += 0.02`)되었다가 스킬 종료 시 페이드 아웃 되도록 부드러운 전환 효과를 구현했습니다.

## 3. 보스전 특수 패턴 (Stage 4) 설계
1. **A+ 아이템 복제**: 패들과 충돌 시, 새로운 공을 배열에 `push`하여 멀티볼 스케일링.
2. **에러 블록(장애물) & F학점 디버프 설치**: 보스 주변에 물리 충돌 판정을 가지는 "큰따옴표" 장애물 설치 및 패들 크기를 반감시키는 F학점 투사체 수직 낙하.
3. **블랙홀 패턴**: 보스 체력 감소 시 `while(true)` 블랙홀이 나타나 공의 벡터에 거리 반비례 중력을 가해 궤도를 휨 (현재 기획에 맞춰 보스전에 한정하여 활성화 상태 관리).

## 4. 메인 렌더링 루프 `draw` 및 물리 파이프라인

`requestAnimationFrame(draw)`에 의해 초당 60회 속도로 루프 연산되는 물리 파이프라인입니다.

1. **중복 루프 방지 (배속 버그 해결)**:
   * **이슈**: 사용자가 ESC(일시정지) 키를 빠르게 연타하거나 화면 이동 버튼을 누를 때, 기존의 루프가 종료되지 않은 상태에서 새로운 `draw()`가 호출되어 게임 속도가 2배, 3배로 중첩 가속되는 크리티컬 버그가 있었습니다.
   * **해결**: `togglePause()` 및 `startGame()` 함수 등 `draw()`를 명시적으로 트리거하는 모든 지점 직전에 `cancelAnimationFrame(animationId)`를 호출하여 **오직 단 하나의 루프 인스턴스만 실행**되도록 안전장치를 설계했습니다.

2. **공과 직사각형 충돌 (Circle-AABB)**:
   * 공과 패들, 블록 사이의 충돌을 `Closest Point on AABB` 방식으로 계산.
   * `distance <= radius` 시 깊이 보정(`overlap = radius - distance`)으로 벽 파고듦을 막고, 벡터 내적 분할 방식으로 반사 각도 적용.

3. **패들 윗면 유도탄 각도 매핑**:
   * 패들 타격 위치 정규화(`-1.0 ~ 1.0`) 후 최대 각도 60도 매핑을 통한 기하학적 반사.

4. **다중 공 바닥 추락 판정**:
   * 캔버스 하단을 넘어가면 `balls` 배열에서 제거(`splice`). `balls.length === 0`일 경우에만 목숨 차감 후 리스폰.
