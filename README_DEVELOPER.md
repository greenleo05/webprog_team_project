# 💻 컴공생 마법소녀의 하루: 기술 사양서 및 개발자 가이드

본 문서는 `game.js` 코드의 작동 메커니즘, 상태 관리 구조, 렌더링 파이프라인, 그리고 수학적 충돌 물리 수식을 상세히 기술합니다. 동료 개발자가 프로젝트를 분석하거나 면접/질의응답을 준비할 때 완벽히 대비할 수 있도록 비유를 제외하고 공학적 관점에서 모든 로직을 설명합니다.

---

## 1. 전역 변수 및 객체 스키마

### 1.1 UI 요소 엘리먼트 바인딩
* `canvas` / `ctx`: 게임 화면을 그리는 `HTMLCanvasElement` 및 2D 렌더링 컨텍스트.
* `scoreDisplay`, `livesDisplay`, `timeDisplay`, `stageNameDisplay`, `timerDisplay`: 실시간 UI 데이터 바인딩 엘리먼트.
* `pauseBtn`, `pauseOverlay`, `settingsOverlay` 등: 모달 제어용 DOM 객체.

### 1.2 이미지 로딩 및 실시간 픽셀 전처리 (CORS 대응)
* `magicalGirlImg` 객체를 로드한 즉시 인메모리 캔버스(`tempCanvas`)를 활용해 `getImageData`로 RGBA 픽셀 배열을 분석합니다.
* 픽셀 데이터 루프를 돌며 R > 240, G > 240, B > 240에 해당하는 흰색 및 미색 영역의 알파 채널(`data[i+3]`)을 `0`으로 수정하여 투명 처리를 수행합니다.
* **CORS 방어**: 로컬 파일 시스템에서 직접 `index.html`을 브라우저에 띄울 경우 보안 규칙에 의해 `getImageData`가 거부(SecurityError)될 수 있으므로, `try-catch` 블록으로 이를 감싸 에러 발생 시 원본 이미지를 그대로 대체하게 처리했습니다.

### 1.3 게임 제어 및 상태 변수
* `isGameRunning` / `isPaused`: 메인 루프 업데이트와 사용자 입력을 분기하기 위한 플래그 변수.
* `isDevMode`: 개발자 모드(테스트용, 쉬움)와 일반 유저 모드(어려움) 간의 분기를 제어하는 전역 상태 변수. 타일 배치 수 및 보스 패턴 난이도에 관여합니다.
* `score` (총 누적 점수), `lives` (플레이어 잔여 목숨, 기본 시작 시 3), `currentStageIndex` (현재 활성화된 스테이지 배열 인덱스).
* `maxUnlockedStage`: 로컬스토리지 `maxUnlockedStage` 키값에서 가져온 도달 최고 스테이지(기본값 0).
* `timeLeft` (남은 시간 초), `lastTime` (1초 단위 틱 판정).
* `BASE_SPEED`: 공의 전체 속력 크기를 정의하는 스칼라 상수 (`Math.sqrt(3*3 + 3*3) ≈ 4.24`). 방향 벡터 분할이 일어나더라도 언제나 일정한 물리 속력을 가지도록 수학적인 기준으로 삼습니다.

### 1.4 핵심 물리 객체 스키마
* **`paddle`**: 가로 크기(`width`), 세로 크기(`height`), 좌표(`x`, `y`), 디버프 타이머(`debuffTimer`), 색상 정보 정의.
* **`balls`**: 다중 공 지원을 위한 배열. 각 객체는 중심 좌표(`x`, `y`), 속도 벡터(`dx`, `dy`), 반지름(`radius`), 리스폰 제어 필드(`isRespawning`, `respawnTimer`)를 포함합니다.
* **`bricks`**: `bricks[col][row]`의 구조를 갖는 2차원 배열. 벽돌 객체는 `{ x, y, status, hp, type, offsetX }` 형태를 가집니다.
* **`boss`**: 5스테이지 보스 오브젝트. 체력(`hp`), 상태 페이즈(`phase`), 활성화 상태(`active`), 이동 속도 벡터(`dx`, `dy`), 각종 쿨다운 타이머(`lastHitTime`, `lastItemDrop`, `lastProjectile`)를 포함합니다.
* **`items` & `projectiles`**: 보스가 드랍하는 A+ 아이템과 F 학점/에러 블록을 추적하는 배열.
* **`blackhole`**: 보스의 체력이 50% 이하일 때 생성되는 좌표(`x`, `y`) 및 반지름 반경 정보를 담은 객체.

## 2. 스테이지 생명 주기 및 데이터 관리

`stages` 배열의 각 원소는 아래 속성을 갖는 독립된 시나리오 객체입니다.
* `time` (UI 표기용 문자열), `name` (스테이지명), `desc` (설명글), `bgColor` (게임 백그라운드 색상)
* `init()` (벽돌 상태 및 플레이 영역 크기 초기 설정)
* `update()` (매 프레임 호출되는 스테이지 한정 상태 갱신 루틴)
* `isCleared()` (클리어 검증 함수)

### 2.1 각 스테이지 구성 정보 및 기믹 상세
`isDevMode` 값에 따라 타격해야 할 벽돌의 수와 기믹이 동적으로 분기됩니다.

1. **Stage 0 (지하철 - 등굣길) [08:00]**
   * 패들 크기: 150px
   * 벽돌 레이아웃: 개발자 모드 `2×5`, 유저 모드 `5×9`. 
   * **기믹**: 모든 블록은 일반 사각형이 아닌 `Canvas API`를 사용해 사람(픽토그램) 형태로 세밀하게 드로잉됩니다(`w: 30`, `h: 45`). `isTroll` 판정(15% 확률)을 받은 빌런 블록(체력 3)은 머리에 빨간 뿔이 달리며 충돌 시 구별되도록 그려집니다.

2. **Stage 1 (교수님의 지루한 수업) [10:00]**
   * 패들 크기: 150px
   * 벽돌 레이아웃: 개발자 모드 `2×6`, 유저 모드 `4×8`. 
   * **기믹**: 강의실 컨셉에 맞추어 `ctx.rect` 및 `ctx.moveTo`를 조합해 텍스트(교수님의 멘트)가 들어가는 "네모난 말풍선" 형태로 렌더링됩니다(`renderW: 120`). 트롤 블록은 붉은 배경과 선으로 강조됩니다.

3. **Stage 2 (점심 보상 스테이지 - 학식) [12:00]**
   * 패들 크기: 250px
   * 벽돌 레이아웃: 개발자 모드 `1×5`, 유저 모드 `4×9`. 
   * **기믹**: 4가지 음식 타입(`food_sandwich`, `food_cake`, `food_drink`, `food_orange`) 중 하나가 난수에 의해 할당됩니다. 이후 렌더링 시 해당 타입 문자열에 따라 샌드위치, 케이크, 음료 컵, 오렌지의 그래픽이 `Arc`, `Rect`, `Line` 조합으로 정교하게 그려집니다. 바닥 충돌 시 `dy = -Math.abs(dy)`로 공을 강제로 위로 튕기며 무적 상태를 제공합니다.

4. **Stage 3 (조별과제) [17:00]**
   * 패들 크기: 150px
   * 벽돌 레이아웃: 개발자 모드 `2×5`, 유저 모드 `5×9`
   * **기믹**: 메신저 채팅방 컨셉으로 핑퐁 말풍선 모양(`isRight` 플래그)을 구현하여 그려집니다. 무임승차(트롤) 조원 블록이 최소 1개 이상 무조건 등장하도록 `hasTroll` 검증 로직이 추가되었으며, 일반 블록과 달리 이들은 `b.dy` 값을 가져 바닥으로 점점 낙하합니다. 패들이나 공으로 막지 못하고 바닥에 떨어질 시 `-100점` 패널티와 함께 사방으로 튀는 파티클(Particles) 이펙트를 발생시킵니다.

5. **Stage 4 (과제 - 버그 물리치기) [23:00]**
   * 패들 크기: 150px
   * 보스 세팅: `boss` 객체를 Phase 1, 비활성화(`active: false`), 체력 `20`(유저 모드 `50`)으로 초기 설정. 에러 코드 벽돌이 모두 파괴되면 전투 페이즈(Phase 3) 진입. 
   * **버그 수정 사항**: 보스 체력 바 렌더링 시 체력 비율(`hp / maxHp`)이 1을 초과하여 UI 영역 밖으로 삐져나가는 버그가 있었습니다. 이를 해결하기 위해 `Math.max(0, Math.min(1, hpRatio))` 연산을 통한 바운드 강제 고정(Clamp) 처리를 반영하여 시각적 결함을 원천 차단했습니다.

## 3. 보스전 특수 패턴 (Stage 4) 설계
보스 페이즈(Phase 3) 진입 시 다음과 같은 패턴 인공지능이 백그라운드에서 주기적으로 발동됩니다.

1. **A+ 아이템 복제 (8초 주기)**: `items` 배열에 A+ 텍스트 투사체가 `dy=2` 속도로 수직 낙하합니다. 패들과 충돌 시, 기존 활성화된 첫 번째 공(`balls[0]`)의 정보를 참조하여 방향 벡터를 뒤집은(`newBall.dy = -Math.abs(dy)`) 완전히 새로운 공을 `balls` 배열에 `push`합니다. 다중 공(Multi-ball) 스케일링을 지원합니다.
2. **에러 블록(장애물) & F학점 디버프 설치 (3초 주기)**:
   * **70% 확률 (장애물)**: 보스 주변 허공에 직사각형의 큰따옴표(`""`) 블록 오브젝트를 배치(`dx=0, dy=0`)합니다. 이 블록은 투사체가 아닌 물리 엔진상 사각형 강체로 취급되며 공이 닿으면 반사됩니다. 최초 타격 시 작은따옴표(`''`)로 문자열 상태가 변환되며, 2회 피격 시 삭제되어 점수를 부여합니다.
   * **30% 확률 (디버프)**: 패들을 향해 `F` 문자 형태의 투사체가 붉은색 텍스트 베이스라인(middle) 조정을 거쳐 수직 낙하(`dy=3`)합니다. 공을 통과하지만 패들과 AABB 교차 충돌 시 5초 동안 패들 가로 넓이를 절반(75px)으로 강제 고정하는 디버프가 적용됩니다.
3. **무한 루프 블랙홀 (체력 50% 이하)**:
   캔버스 중앙에 `while(true)` 텍스트를 가진 `blackhole`을 생성합니다. 메인 루프에서 모든 공들의 위치와 블랙홀 사이의 거리를 측정하여 반경 150px 내에 들어오면 해당 공의 `dx, dy` 벡터에 거리 반비례 중력(`(dx/dist)*0.15`)을 가산한 후 속도를 `BASE_SPEED`로 정규화하여 경로가 중심점으로 휘어지도록 설계했습니다.

## 4. 메인 렌더링 루프 `draw` 및 물리 파이프라인

`requestAnimationFrame(draw)`에 의해 초당 60회 속도로 지속 루프 연산되는 게임 루프 시퀀스입니다. 텍스트 오브젝트(`A+`, `F`, `""` 등)의 경우 `textBaseline = "middle"` 설정을 통해 시각적 렌더링 중심과 물리 AABB 박스의 중앙값을 일치시켜 충돌 괴리를 방지합니다.

1. **오브젝트 배열 순회 및 생명 주기 연산**:
   `balls`, `items`, `projectiles` 등의 상태를 역순 `for` 루프(요소 삭제로 인한 인덱스 밀림 현상 방지)로 업데이트합니다.
2. **공과 직사각형 충돌 (Circle-AABB)**:
   공과 패들, 그리고 동적 에러 블록(`quote`) 사이의 충돌을 `Closest Point on AABB` 방식으로 계산합니다.
   `distance <= radius` 이면 충돌이 발생한 것이며, 깊이 보정(`overlap = radius - distance`)을 통해 좌표를 밀어낸 후 내적 연산을 통해 방향 벡터(`dx, dy`)를 반사시킵니다.
3. **패들 윗면 유도탄 각도 매핑**:
   패들 중앙 기준점 타격 위치를 정규화(`-1.0 ~ 1.0`) 한 후 최대 각도 60도(`Math.PI / 3`)를 매핑하여 플레이어가 원하는 각도로 공을 퍼올릴 수 있는 기하학적 반사 연산을 수행합니다.
4. **다중 공 바닥 추락 판정**:
   `balls` 배열 안의 원소가 캔버스 하단 경계를 넘으면 `splice`로 제거합니다. `balls.length === 0` 즉, 배열 내의 공이 하나도 남지 않았을 경우에만 플레이어 목숨을 1 차감하고 새 공을 재생성 모드(`isRespawning`)로 큐에 넣습니다.

## 5. UI 드로잉 및 이펙트 파이프라인

### 5.1 3D 입체 베벨 효과 구현 (`drawPixelBlock`)
레트로 디테일을 위한 드로잉 메서드로 아래의 드로잉 과정을 포함합니다.
1. `ctx.fillRect(x, y, w, h)`에 `#000` (검은색) 컬러를 채워 테두리 외곽 레이어를 구성합니다.
2. 2픽셀 안쪽 여백에 타겟 컬러로 내부 면적을 덮어씌웁니다.
3. 좌측/상단 방향으로 두께 3px짜리 반투명 흰색 영역을 그려 돌출 형태의 하이라이트 베벨을 생성합니다.
4. 우측/하단 방향으로 동일하게 3px 크기의 반투명 검은색 섀도우를 그려 들어가 보이는 음영 깊이감을 유도합니다.

### 5.2 파티클(Particles) 물리 이펙트
Stage 3 조별과제 스테이지 등에서 특정 이벤트(예: 트롤 블록의 추락 등)가 발생할 때 시각적 타격감과 패널티 피드백을 주기 위해 `particles` 배열 객체가 생성됩니다.
1. 파티클은 기준점 `x, y`를 시작으로 360도 전 방향 임의의 속도 벡터 `dx, dy`를 가집니다.
2. 매 프레임 `life` 타이머가 감소하며 0이 되면 배열에서 제거됩니다.
3. 캔버스에 그릴 때는 `rgba()` 컬러 스키마를 사용하여 파티클의 `life` 값에 비례하여 알파(투명도) 수치가 낮아지는 페이드 아웃 기법을 구현했습니다.

### 5.3 모드 및 오버레이 블러 제어
`main-screen`, `pause-overlay` 등의 CSS에 `backdrop-filter: blur(8px)`를 적용하여 백그라운드 WebGL 캔버스의 동적 렌더링 상태를 흐리게 블러 아웃합니다. 이는 일시정지, 게임 오버 시 플레이어의 이목을 텍스트 팝업으로 집중시키는 현대적 모달 연출입니다.
